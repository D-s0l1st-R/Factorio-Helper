# ПОЯСНИТЕЛЬНАЯ ЗАПИСКА
## к файлам данных предметов и рецептов игры Factorio: Space Age

### 1. Введение

В рамках работы были подготовлены два структурированных файла в формате JSON, содержащих сведения об игровых объектах и рецептах игры Factorio с дополнением Space Age.

Цель работы — преобразовать исходные игровые данные в удобный для чтения, хранения и программной обработки формат. Полученные файлы могут использоваться при разработке вспомогательных программ, справочных систем, калькуляторов производства, анализаторов игровых данных и других приложений, связанных с механиками Factorio.

Для разделения информации по назначению были созданы два отдельных файла:

- `factorio_items.json` — содержит характеристики игровых прототипов;
- `factorio_recipes.json` — содержит сведения об игровых рецептах.

Разделение данных позволяет упростить их обработку и использовать только необходимую информацию в зависимости от задач разрабатываемого программного обеспечения.

### 2. Источник исходных данных

В качестве исходного материала использовался файл `raw.json`, содержащий выгрузку внутренних игровых данных Factorio.

Несмотря на расширение `.json`, исходный файл представляет собой сериализованное представление Lua-таблицы `data.raw`. В этой структуре хранятся описания различных игровых прототипов: предметов, технологий, рецептов, производственных объектов и других элементов игры.

Исходная структура была обработана специальным разборщиком, после чего полученные данные были преобразованы в стандартный формат JSON.

При обработке данные разделялись по категориям прототипов. Категория `recipe` была выделена отдельно, поскольку содержит информацию о производственных рецептах, тогда как остальные категории относятся к другим игровым объектам и характеристикам.

### 3. Описание файла factorio_items.json

Файл `factorio_items.json` предназначен для хранения сведений об игровых прототипах Factorio, за исключением рецептов.

В файл включены не только обычные предметы, но и другие категории игровых объектов, в том числе служебные и скрытые прототипы, присутствующие в исходной выгрузке.

Общее количество категорий прототипов в файле составляет 250, количество отдельных прототипов — 4476.

Основная структура файла:

| Поле | Назначение |
|---|---|
| `game` | Название игры |
| `data_scope` | Описание состава данных |
| `source_dump` | Название исходного файла |
| `prototype_category_count` | Количество категорий прототипов |
| `prototype_count` | Общее количество прототипов |
| `prototypes` | Основной раздел с игровыми прототипами |

В разделе `prototypes` данные сгруппированы по категориям. Внутри каждой категории располагаются отдельные прототипы, доступные по их внутренним именам.

Например, путь к аккумулятору:

`prototypes.accumulator.accumulator`

Первый уровень (`accumulator`) обозначает категорию прототипа, второй (`accumulator`) — имя конкретного объекта.

Каждый прототип содержит собственный набор характеристик. Например, у производственного объекта могут присутствовать параметры здоровья, графики, размеры, источники энергии, изображения и другие свойства.

Важно учитывать, что состав характеристик зависит от типа прототипа. Не все поля присутствуют у каждого объекта.

### 4. Описание файла factorio_recipes.json

Файл `factorio_recipes.json` предназначен для хранения информации о производственных рецептах Factorio.

В нём содержится 659 рецептов, извлечённых из категории `recipe` исходной структуры `data.raw`.

Основная структура файла:

| Поле | Назначение |
|---|---|
| `game` | Название игры |
| `data_scope` | Описание состава данных |
| `source_dump` | Название исходного файла |
| `recipe_count` | Общее количество рецептов |
| `recipes` | Основной раздел с рецептами |

Каждый рецепт располагается внутри объекта `recipes` и доступен по своему внутреннему имени.

Например:

`recipes.iron-plate`

Основные характеристики рецепта:

| Поле | Назначение |
|---|---|
| `name` | Внутреннее имя рецепта |
| `type` | Тип прототипа |
| `category` | Категория производства |
| `energy_required` | Время выполнения рецепта |
| `ingredients` | Список входных компонентов |
| `results` | Список производимых результатов |
| `enabled` | Признак доступности рецепта по умолчанию, если присутствует |

Каждый элемент массива `ingredients` описывает входной компонент, а каждый элемент `results` — результат производства.

Пример рецепта:

```json
{
  "name": "iron-plate",
  "type": "recipe",
  "category": "smelting",
  "energy_required": 3.2,
  "ingredients": [
    {
      "amount": 1,
      "name": "iron-ore",
      "type": "item"
    }
  ],
  "results": [
    {
      "amount": 1,
      "name": "iron-plate",
      "type": "item"
    }
  ]
}
```

В данном примере для изготовления одной железной пластины требуется одна единица железной руды. Производство относится к категории `smelting`, а время выполнения рецепта составляет 3,2 секунды.

### 5. Структура и формат хранения данных

Для хранения информации был выбран формат JSON (JavaScript Object Notation).

JSON представляет собой текстовый формат обмена данными, основанный на использовании пар «ключ — значение», массивов и вложенных объектов.

Основными преимуществами данного формата являются:

- простота чтения и редактирования;
- поддержка большинством современных языков программирования;
- возможность хранения сложных вложенных структур;
- удобство передачи данных между программными компонентами;
- отсутствие необходимости в специализированной системе управления базами данных для чтения файлов.

В созданных файлах используется иерархическая структура. Общие сведения располагаются на верхнем уровне, а основные игровые данные находятся во вложенных объектах.

Такой подход позволяет обращаться к нужной категории или конкретному прототипу без необходимости обрабатывать весь массив данных вручную.

# 6. Инструкция для разработчика

В данном разделе описывается порядок подключения JSON-файлов к программному проекту, получения данных и организации взаимодействия между ними.

## 6.1. Размещение файлов в проекте

## 6.2. Загрузка JSON-файлов

Перед обращением к данным необходимо загрузить оба файла в оперативную память приложения.

Пример реализации на Python:

```python
import json
from pathlib import Path

DATA_DIR = Path("data")

def load_json(filename):
    path = DATA_DIR / filename

    with open(path, "r", encoding="utf-8") as file:
        return json.load(file)


items_data = load_json("factorio_items.json")
recipes_data = load_json("factorio_recipes.json")
```

После выполнения загрузки переменная `items_data` будет содержать информацию об игровых прототипах, а `recipes_data` — информацию о рецептах.

Для работы с JSON рекомендуется использовать кодировку UTF-8.

При загрузке следует предусмотреть обработку ошибок:

- отсутствие файла;
- повреждение JSON;
- отсутствие обязательных разделов;
- несоответствие ожидаемой структуры.

Пример проверки:

```python
if "prototypes" not in items_data:
    raise ValueError("В файле отсутствует раздел prototypes")

if "recipes" not in recipes_data:
    raise ValueError("В файле отсутствует раздел recipes")
```

## 6.3. Получение конкретного прототипа

Структура файла `factorio_items.json` позволяет получать объект по двум параметрам:

1. Категория прототипа.
2. Внутреннее имя объекта.

Например, чтобы получить характеристики аккумулятора:

```python
accumulator = (
    items_data["prototypes"]
    .get("accumulator", {})
    .get("accumulator")
)

if accumulator is not None:
    print(accumulator)
```

Для получения отдельного свойства объекта:

```python
if accumulator:
    print(accumulator.get("max_health"))
    print(accumulator.get("energy_source"))
    print(accumulator.get("icon"))
```

Использование метода `.get()` предпочтительнее прямого обращения к ключам, поскольку отдельные характеристики могут отсутствовать.

## 6.4. Поиск прототипа по имени

Если разработчику известно только внутреннее имя объекта, можно выполнить поиск по всем категориям.

Пример:

```python
def find_prototype(items_data, prototype_name):
    prototypes = items_data.get("prototypes", {})

    for category, objects in prototypes.items():
        if prototype_name in objects:
            return {
                "category": category,
                "data": objects[prototype_name]
            }

    return None


result = find_prototype(items_data, "iron-ore")

if result:
    print("Категория:", result["category"])
    print("Данные:", result["data"])
else:
    print("Прототип не найден")
```

Данный способ позволяет искать объекты без предварительного знания категории.

Для ускорения поиска при запуске приложения рекомендуется один раз построить дополнительный индекс прототипов.

Пример:

```python
def build_prototype_index(items_data):
    index = {}

    for category, objects in items_data["prototypes"].items():
        for name, prototype in objects.items():
            index[name] = {
                "category": category,
                "data": prototype
            }

    return index


prototype_index = build_prototype_index(items_data)

iron_ore = prototype_index.get("iron-ore")
```

После создания индекса поиск по имени выполняется без повторного перебора всех категорий.

Следует учитывать, что внутренние имена не стоит считать гарантированно уникальными между всеми категориями. Если требуется однозначная идентификация объекта, необходимо использовать пару «категория + имя».

## 6.5. Получение рецепта по названию

В файле `factorio_recipes.json` все рецепты находятся в разделе `recipes`.

Получить конкретный рецепт можно по его внутреннему имени:

```python
recipe = recipes_data["recipes"].get("iron-plate")

if recipe:
    print("Категория:", recipe.get("category"))
    print("Время:", recipe.get("energy_required"))
    print("Ингредиенты:", recipe.get("ingredients"))
    print("Результаты:", recipe.get("results"))
```

Для получения всех рецептов определённой категории производства:

```python
def get_recipes_by_category(recipes_data, category):
    result = []

    for recipe in recipes_data["recipes"].values():
        if recipe.get("category") == category:
            result.append(recipe)

    return result


smelting_recipes = get_recipes_by_category(
    recipes_data,
    "smelting"
)
```

Таким образом, разработчик может получать рецепты плавки, электроники, химического производства и других категорий.

## 6.6. Получение ингредиентов и результатов рецепта

Для анализа производственных цепочек необходимо обрабатывать массивы `ingredients` и `results`.

Пример получения компонентов рецепта:

```python
recipe = recipes_data["recipes"].get("advanced-circuit")

if recipe:
    for ingredient in recipe.get("ingredients", []):
        print(
            ingredient.get("name"),
            ingredient.get("amount"),
            ingredient.get("type")
        )
```

Результатом выполнения будет список входных компонентов с их количеством и типом.

Аналогичным образом можно получить производимые объекты:

```python
if recipe:
    for result in recipe.get("results", []):
        print(
            result.get("name"),
            result.get("amount"),
            result.get("type")
        )
```

Важно: разработчик не должен предполагать, что каждый рецепт имеет только один ингредиент или один результат. Оба поля являются массивами и могут содержать несколько элементов.

Кроме того, в рецептах могут использоваться как предметы (`item`), так и жидкости (`fluid`).

## 6.7. Связь между файлами

Для полноценной работы приложения необходимо связывать рецепты с прототипами.

Связь осуществляется по внутреннему имени объекта.

Например, рецепт `iron-plate` содержит ингредиент `iron-ore`. Чтобы получить полные характеристики железной руды, программа должна выполнить поиск прототипа с именем `iron-ore` в файле `factorio_items.json`.

Пример:

```python
recipe = recipes_data["recipes"].get("iron-plate")

if recipe:
    for ingredient in recipe.get("ingredients", []):
        item_name = ingredient.get("name")

        prototype = find_prototype(
            items_data,
            item_name
        )

        if prototype:
            print("Название:", item_name)
            print("Категория:", prototype["category"])
            print("Характеристики:", prototype["data"])
```

Необходимо учитывать, что не каждый ингредиент рецепта обязательно представлен в файле прототипов в виде обычного предмета. Например, жидкость может относиться к категории `fluid`, а некоторые ссылки могут указывать на другие типы игровых объектов.

Поэтому при поиске желательно учитывать поле `type` у ингредиента или результата.

## 6.8. Пример расчёта количества ресурсов

На основе файла рецептов можно реализовать простой калькулятор потребления ресурсов.

Например, для производства 10 единиц железных пластин используется рецепт `iron-plate`.

```python
def calculate_ingredients(recipes_data, recipe_name, quantity):
    recipe = recipes_data["recipes"].get(recipe_name)

    if recipe is None:
        return None

    results = {}

    for ingredient in recipe.get("ingredients", []):
        name = ingredient.get("name")
        amount = ingredient.get("amount", 0)

        if name:
            results[name] = (
                results.get(name, 0) + amount * quantity
            )

    return results


required = calculate_ingredients(
    recipes_data,
    "iron-plate",
    10
)

print(required)
```

Для указанного примера программа рассчитает потребность в 10 единицах железной руды.

Данный алгоритм представляет собой базовый расчёт. Для полноценного производственного калькулятора потребуется учитывать альтернативные результаты, вероятности выпадения, ограничения рецептов, производительность оборудования, бонусы, качество и другие игровые механики.

## 6.9. Рекомендуемые правила обработки данных

Для корректной работы с файлами необходимо соблюдать следующие правила:

1. Не изменять исходные JSON-файлы непосредственно в процессе работы приложения.
2. Загружать файлы один раз при запуске, если не требуется динамическое обновление данных.
3. Использовать внутренние имена прототипов для поиска и связывания объектов.
4. Не считать все прототипы обычными предметами: файл `factorio_items.json` содержит разные категории игровых объектов.
5. Не предполагать наличие одинакового набора полей у всех прототипов.
6. Проверять существование ключей перед чтением значений.
7. Обрабатывать массивы `ingredients` и `results` как списки произвольной длины.
8. Учитывать тип компонента: `item` или `fluid`.
9. Не считать время рецепта обязательным параметром: если `energy_required` отсутствует, необходимо предусмотреть отдельную обработку.
10. Не использовать название объекта как единственный способ идентификации, если требуется однозначное определение категории прототипа.

## 6.10. Рекомендуемая внутренняя структура данных приложения

Для удобства разработки рекомендуется после загрузки JSON-файлов сформировать следующие структуры:

| Структура | Назначение |
|---|---|
| `items_data` | Исходные данные всех прототипов |
| `recipes_data` | Исходные данные всех рецептов |
| `prototype_index` | Индекс прототипов для быстрого поиска |
| `recipe_index` | Индекс рецептов по внутренним именам |
| `recipes_by_category` | Группировка рецептов по категориям производства |

Пример создания индекса рецептов:

```python
recipe_index = {
    name: recipe
    for name, recipe
    in recipes_data["recipes"].items()
}
```

Пример группировки рецептов:

```python
from collections import defaultdict

recipes_by_category = defaultdict(list)

for recipe in recipes_data["recipes"].values():
    category = recipe.get("category", "unknown")
    recipes_by_category[category].append(recipe)
```

Такая организация позволяет разделить хранение исходных данных и логику их обработки.

При необходимости данные можно дополнительно преобразовать в классы или модели предметной области, однако это не является обязательным условием для чтения JSON-файлов.

### 7. Проверка и ограничения данных

После преобразования оба файла были сохранены в формате JSON и проверены на корректность синтаксической структуры.

Результаты обработки:

| Показатель | Значение |
|---|---:|
| Количество категорий в исходной структуре | 251 |
| Категорий в `factorio_items.json` | 250 |
| Количество прототипов | 4476 |
| Количество рецептов | 659 |
| Количество итоговых файлов | 2 |

При использовании данных необходимо учитывать особенности исходной выгрузки.

В исходном файле присутствует отметка о том, что при сериализации некоторые общие ссылки и циклические связи были пропущены. Поэтому полученные JSON-файлы отражают доступное содержимое выгрузки, но не гарантируют сохранение абсолютно всех внутренних связей между игровыми объектами.

Кроме того, точная версия игры, из которой была получена выгрузка, в имеющихся исходных сведениях не установлена. Поэтому при использовании файлов для разработки программ, рассчитанных на определённую версию Factorio: Space Age, рекомендуется предварительно сверить данные с соответствующей версией игры.

### 8. Заключение

В результате работы были подготовлены два JSON-файла, содержащих структурированные данные игры Factorio: Space Age.

Исходные данные были извлечены из структуры `data.raw`, обработаны и преобразованы в формат JSON. Полученные файлы имеют разделённую по назначению структуру, что упрощает их дальнейшее использование в программных приложениях.

В пояснительную записку также включены рекомендации по подключению файлов к программному проекту, поиску прототипов и рецептов, получению характеристик, обработке ингредиентов и связыванию информации между двумя наборами данных.

Предложенная архитектура позволяет использовать файлы как основу для разработки справочных и аналитических инструментов, а также программ для расчёта и планирования производственных процессов в Factorio: Space Age.
